# Permission Matrix — Input Evidence (Discovery Doc + Forms 20–24)

**Purpose/scope:** this is a transcription-and-tagging evidence file, not the permission matrix itself. It feeds the main session's synthesis of `distillation/permission-matrix.md` (item 5). Nothing here is resolved or collapsed — every table/statement is transcribed close to verbatim, with exact line numbers into `NextGen_Portal_Discovery.txt` and exact role labels as written (not normalized to the canonical Hierarchy Tier/Functional Group vocabulary in `entity-model.md`). Tagging follows `open-questions.md`'s convention: **CONFIRMED** (client's actual current practice — rare in this doc), **PROPOSED** (vendor-voice "the system should..." language — the overwhelming majority of what follows; every table headed "Recommended System Permission Structure" or "Recommended Permission Structure" is PROPOSED by default), **CONTRADICTED** (conflicts with another statement elsewhere — see the dedicated section below), **UNANSWERED** (asked, not really answered).

Per the register's standing methodological caveat: NextGen has zero active clients, so "current process" language throughout this doc describes intended/designed process, not tested practice — treat as PROPOSED even where the prose uses present tense.
